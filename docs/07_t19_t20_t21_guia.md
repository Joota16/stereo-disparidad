9. T19: capturar parámetros por configuración en metadatos.

## Prueba breve de T19 (sin usar la laptop)

```powershell
.\.venv\Scripts\python.exe -m experiments.run_benchmark_grid `
  --scope quick --reps 1 --warmup 0 `
  --output-runs results\piloto_local\runs.csv `
  --output-summary results\piloto_local\summary.csv
```

El modo `distribuido_loopback` es un **control de funcionamiento**, no el experimento distribuido PC+laptop.
Para dos nodos, iniciar el trabajador ZeroMQ en la laptop y pasar `--connect tcp://<IP_LAPTOP>:5555`.
El puerto y direcciones son parámetros locales, nunca hardcodearlos en scripts.
No abrir el servidor a Internet: el protocolo no incorpora autenticación.

## T21 — Análisis a partir del CSV T19

```powershell
.\.venv\Scripts\python.exe -m experiments.analyze_t21 `
  --runs results\t19_benchmark_runs.csv `
  --output results\t21
```

Para probar con el CSV del piloto local:

```powershell
.\.venv\Scripts\python.exe -m experiments.analyze_t21 `
  --runs results\piloto_local\runs.csv `
  --output results\piloto_local\t21
```

El analizador excluye **automáticamente** los calentamientos y el modo
`distribuido_loopback`. No permite resultados con equivalencia falsa ni tiempos
no positivos. Exporta:

- `t21_resumen.csv` — una fila por configuración y arquitectura.
- `t21_interpretacion.md` — resumen científico con advertencias de alcance.
- `t21_tiempos.png` — mediana del tiempo extremo a extremo.
- `t21_speedup.png` — aceleración frente al secuencial.
- `t21_cruces_observados.csv` — **solo si existe** un cruce observado entre
  tamaños distintos para la misma escena, K y rango de búsqueda.

El script no infiere un umbral exacto, no extrapola a otras configuraciones y
no presenta `speedup/2` como eficiencia de un clúster heterogéneo.
